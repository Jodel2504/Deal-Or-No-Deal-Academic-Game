ISSUE #1: GROUP NAME NOT SHOWING IN ONLINE MODE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📍 Offline (LAN):
   Teacher setup shows:
   ✓ "➕ CREATE NEW GROUP" button
   ✓ "🗂 USE EXISTING GROUP" selector
   ✓ Current group name displayed
   ✓ List of students in group

📍 Online:
   Teacher setup shows:
   ✗ No group selection buttons
   ✗ No group name displayed
   ✗ No student list
   ✗ Confusing - looks incomplete

🔍 ROOT CAUSE:
   Two completely separate code implementations:
   
   Offline path: mpSelectRole('host')
     → mpShowPane('mpHostPane')  [Shows group UI]
   
   Online path: mpSelectRole('host')
     → mpShowPane('mpHostPane')  [Same pane name!]
     → But group UI not visible
     → Different element visibility
   
   The pane is the same, but elements are hidden/shown differently
   based on connection type. Online skips group selection entirely.

✅ SOLUTION:
   Make both online and offline show same group selection UI
   Create mpGroupSelectionPane that displays for BOTH modes
   Show: CREATE NEW GROUP | USE EXISTING GROUP
   Show: Current group name
   Show: Students in group


ISSUE #2: CAN'T ADD GROUPS IN ONLINE MODE  
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📍 Offline:

📍 Online:

   ✗ Can't name the class
   ✗ No group creation option
   ✗ Stuck with no group selection

🔍 ROOT CAUSE:
   Same as Issue #1:
   Online code path skips mpGroupSelectionPane entirely
   Goes straight to room setup
   Group creation UI never shown

✅ SOLUTION:
   Show group creation UI for online mode
   Same code as offline
   Allow online teachers to create/manage groups

ISSUE #3: CUSTOMIZE QUESTIONS BUTTON FLOW PROBLEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📍 Offline:
   1. See buttons: [CUSTOMIZE CASES] [CUSTOMIZE QUESTIONS] [CREATE ROOM]
   2. Click "CUSTOMIZE QUESTIONS" immediately
   3. Modal opens instantly on top (z-index fixed)
   4. Edit questions
   5. Close modal
   6. Return to host setup
   7. Ready to create room
   ✓ STRAIGHTFORWARD

📍 Online:
   1. See buttons but click flow is confusing
   2. Click "CUSTOMIZE QUESTIONS"
   3. Nothing happens OR modal behind other window
   4. Need to click OTHER buttons to get it to appear
   5. Modal finally shows after 2-3 clicks
   6. Frustrating and unclear
   ✗ BROKEN FLOW

🔍 ROOT CAUSE:
   Three problems combined:
   
   a) Z-index conflicts:
      .modal-ov { z-index: 200 }
      Other modals have higher z-index
      Customize modal opens behind them
      
   b) Multiple event handlers:
      showQModal() and other functions
      Button click triggers wrong handler
      Modal show state not properly managed
      
   c) Lack of reflow:
      Browser doesn't force re-render
      Old modal state cached
      Needs CSS reflow to fix
      
   Combined effect: Confusing click flow

✅ SOLUTION:
   1. Increase .modal-ov z-index: 200 → 300
   2. Add #qSetupModal { z-index: 450 !important }
   3. Before showing modal, close all other modals
   4. Force reflow with offsetHeight
   5. Use requestAnimationFrame for smooth show
   6. Unified event delegation for all buttons


ISSUE #4: LINKS NOT FUNCTIONAL - NO AUTO-JOIN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📍 What SHOULD Happen:
   Teacher creates room with code "ABCD1234"
   Teacher copies link: game.com?studentJoin=ABCD1234
   Teacher sends link via email/chat/message
   Student clicks link:
     → Auto-joins student mode
     → Auto-fills code "ABCD1234"
     → Auto-connects to server
     → Goes directly to waiting room
     → Types name
     → Waits for teacher to start game
   ✓ SMOOTH & PROFESSIONAL

📍 What ACTUALLY Happens (Online):
   Student clicks link: game.com?studentJoin=ABCD1234
   → Page loads
   → URL parameter IGNORED
   → Goes to Main Menu
   → Has to click "MULTIPLAYER" button
   → Has to click "I AM A STUDENT"
   → Has to manually type code "ABCD1234"
   → Has to click check code button
   → Finally enters waiting room
   ✗ 5-8 EXTRA CLICKS!

🔍 ROOT CAUSE:
   Multiple issues:
   
   a) Auto-join handler only works for offline:
      handleStudentAutoJoin() calls mpPlayerCheckCode()
      Online uses different connection method (mpConnect)
      Handler doesn't detect online mode
      
   b) Two different code paths:
      Offline: mpPlayerCheckCode() → LocalStorage
      Online: mpConnect() → WebSocket
      Auto-join only triggers offline path
      
   c) Z-index 2000 for mpModal:
      mpModal { z-index: 2000 }
      Too high, blocks everything
      Interferes with auto-join flow
      
   d) No detection of connection mode:
      Auto-join doesn't check mpIsOnline()
      Assumes offline
      Fails silently on online

✅ SOLUTION:
   1. Detect online vs offline mode: mpIsOnline()
   2. For offline: use existing mpPlayerCheckCode()
   3. For online: use mpConnect(code)
   4. Unified auto-join for both modes
   5. Fix z-index so modal doesn't block
   6. Auto-proceed directly to waiting room
   7. No manual navigation needed

THE REAL PROBLEM: TWO SEPARATE IMPLEMENTATIONS
════════════════════════════════════════════════════════════════════════════════

The code has evolved with two parallel multiplayer systems that were
never unified:

OFFLINE (LAN/Hotspot) - Works Well:
  ✓ Group management (database.json)
  ✓ Teacher dashboard
  ✓ Student list per group
  ✓ Auto-join links
  ✓ Customize buttons work
  ✓ Clear UI flow

ONLINE (Internet) - Broken in Multiple Ways:
  ✗ No group selection shown
  ✗ Can't create groups
  ✗ Customize buttons stuck
  ✗ Auto-join doesn't work
  ✗ Different UI from offline
  ✗ Confusing flow

ROOT ISSUE: Two code paths diverge at mpSelectRole()
  
  Online: mpSelectRole('host')
    → Shows bare room setup
    → No groups
    → No students
    → Different buttons
    
  Offline: mpSelectRole('host')
    → Shows group selection
    → Shows students
    → Clear flow
    → All features work

SOLUTION: Merge the two code paths
  Make online behave exactly like offline
  Same UI for both modes
  Same features for both modes
  Same user experience everywhere


════════════════════════════════════════════════════════════════════════════════
WHY THIS HAPPENED
════════════════════════════════════════════════════════════════════════════════

1. Started with offline (LAN) multiplayer - worked great
2. Added online (internet) multiplayer - separate implementation
3. Features added to offline: groups, auto-join, etc.
4. Online multiplayer never updated with new features
5. Result: Two divergent systems

The code was written without central architecture.
Each mode got its own implementation.
No one unified them later.

This is common in evolving codebases - happens to the best!
